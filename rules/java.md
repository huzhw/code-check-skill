# Java 组检查规则（通用层）

> 适用：`.java` 文件，**任何 Java 项目通用**。
> 加载时机：scan 分组输出中「Java」组的文件。
> 🔴 通用规则（`rules/general.md` 的破坏性操作 / 敏感信息 / 路径安全）与本文件**叠加生效**。
> 团队/项目专属规范不在本文件——脚本检测到项目档案会提示加载对应 `rules/profile-*.md`。

## 性能

| 检查点 | 典型隐患 |
|--------|---------|
| 循环内查库/HTTP/Redis/外部 IO | 逐条查库、循环内发请求；正确做法=循环外批量查询→内存分组计算→批量写回 |
| N+1 查询 | 关联对象逐条加载 |
| 大表无索引、全表扫描 | 条件列无索引、子查询失控 |
| 无分页 | 大结果集一次性拉全量 |
| 重复计算 | 循环内重复做可提取的不变计算（长度/正则/对象创建） |

## 健壮性

| 检查点 | 典型隐患 |
|--------|---------|
| 空指针 | 未判空的链式调用、Map.get 后直接用、集合元素可空 |
| 类型转换 | 数字解析失败、强转失败、BigDecimal 精度与比较（用 compareTo 非 equals） |
| 资源未关闭 | 流/连接/Session 未 try-with-resources 或 finally 关闭 |
| 异常吞掉 | catch 后不记日志不上抛、catch(Exception) 掩盖、异常信息丢失（空 catch） |
| 边界值 | 空集合、下标越界、0 除、null 元素 |

## 并发

| 检查点 | 典型隐患 |
|--------|---------|
| 共享可变状态 | 静态变量被多线程读写、SimpleDateFormat 静态共享 |
| 线程安全 | 非线程安全集合进并发场景（HashMap/ArrayList 静态共享） |
| 锁范围 | 锁粒度错、双重检查锁缺 volatile、锁对象可替换 |
| 线程池 | 无界队列堆积、核心参数与场景不匹配、任务异常未处理 |

## 事务

| 检查点 | 典型隐患 |
|--------|---------|
| 多 SQL 写无事务 | 批量 INSERT/UPDATE/DELETE 缺事务注解（`@Transactional(rollbackFor = Exception.class)`） |
| 提交过早 | 事务内调外部 IO（HTTP/文件/MQ），半途失败数据不一致 |
| 事务失效 | 同类内自调用事务方法、方法非 public、异常被 catch 吞掉不回滚 |
| 单条 SQL | 数据库自身保证原子性，不需要事务注解（别误报） |
