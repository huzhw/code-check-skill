# MyBatis XML / SQL 组检查规则（通用层）

> 适用：`.xml`（含 `/dao/` 路径的 Mapper）、`.sql` 文件，**任何项目通用**。
> 加载时机：scan 分组输出中「MyBatis XML/SQL」「SQL 脚本」组。
> 🔴 通用规则（`rules/general.md` 的破坏性操作 / 敏感信息 / 路径安全）与本文件**叠加生效**。
> 特定数据库方言（达梦/Oracle/MySQL 差异等）不在本文件——按项目档案或仓库自定义规范加载。

## 注入安全

| 检查点 | 典型隐患 |
|--------|---------|
| `${}` 拼接 | ORDER BY / 列名用 `${}` 且值来自前端 → SQL 注入；确认白名单校验 |
| `#{}` 缺失 | 字符串拼 SQL、Statement 拼接 |
| 动态表名 | `${tableName}` 分表必须有服务端白名单/工具类拼装，禁止前端直传 |
| LIKE 注入 | LIKE 参数未转义 `%`/`_`（功能缺陷）或拼接注入 |

## 数据表操作核对 🔴（检查报告专用表格）

diff 里**每处 SQL**（Mapper XML / @Select / JDBC / 存储过程调用）都要核对：涉及的**库（schema）+ 表名 + 操作类型**；UPDATE/DELETE/MERGE 必须写明**变更字段 + 定位条件（WHERE/ON）**。

报告输出两张表（写操作重点核对，查询仅核对表名）：

### 🗄️ 数据表写操作（增删改，重点核对）
| 库/SCHEMA | 表名 | 操作 | 变更字段（更新/插入啥） | 定位条件（根据啥） | 来源 |
|---|---|---|---|---|---|
| 本库 | T_XXX | DELETE | —（删行） | WHERE id | XxxMapper.xml:31 |

### 🔍 数据表查询（SELECT，仅核对表名）
| 库/SCHEMA | 表名 | 来源 |
|---|---|---|
| 本库 | SYS_XXX（联查 A / B，分页） | XxxMapper.xml:36 |

规则：
- 写操作按语句主类型标 INSERT/UPDATE/DELETE/MERGE；MERGE 匹配/不匹配两分支分别写
- 详略分流：INSERT 不展开（变更字段、定位条件填「—」）；UPDATE/DELETE/MERGE 是核对重点
- 变更字段：≤6 个全列，>6 个列前 3 个 +「等 N 个字段」；DELETE 填「—（删行）」
- 定位条件必填：UPDATE/DELETE 填 WHERE 键，MERGE 填 ON 键；动态表名标注分表
- 只列本次 diff 实际涉及的表；库名 = SQL schema 前缀或 datasource 归属，无前缀标「本库」
- 用途：核对删了啥/按啥删、按啥更新/更新了啥；表名写错库、拼错、张冠李戴

## 高危写法

| 检查点 | 隐患 |
|--------|------|
| UPDATE/DELETE 无 WHERE | 全表误改误删 → 必须列影响范围和可恢复性，拿不准标「待确认」 |
| WHERE 恒真 | `WHERE 1=1` 且无其他条件、动态条件全空时全表命中 |
| MERGE/ON 条件错 | ON 键不唯一导致重复匹配、匹配分支字段漏更新 |
| 批量语句规模 | 全量集合直传批量 INSERT/UPDATE（不分批）——大集合下驱动参数超限/超长事务风险；分包工具与上限按项目规范定 |
